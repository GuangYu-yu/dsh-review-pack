# code 的已知形态

判据在 `references/code.md`。这里是常见形态，用来召回——**不是全集**，形态对不上而判据对得上时，按判据判。

## 死代码

- 定义了但从未被调用的函数、方法、类型
- 导出或公开但没有任何外部引用
- 赋值后从未被读取的变量；声明后从未被使用的常量与配置项
- 引入但没实际用到的依赖
- 定义了但从未被抛出的错误类型
- 注册表里登记了、但没有任何执行器认领的条目（插件清单、路由表、命令映射、回调数组）——登记不等于实现，"登记表看起来是全的"正是它不被发现的原因

## 不可达

- 永远进不去的条件分支；恒真或恒假的条件
- 无条件终止流程之后仍然写着的代码
- 永远不会被触发的捕获块

## 冗余

- 空函数体；捕获异常后只做原样重抛
- 仅透传参数的包装层；中间对象只负责转发而不贡献语义的链式调用
- 只有一个实现、且该实现并不需要被替换的抽象（判断依据见 `references/architecture.md` 的"抽象是否被证成"，该不该留见"设计凭什么存在"）
- 被注释保留的旧代码
- 复述代码本身的注释

## 重复

- 逻辑完全相同的段落
- 同一常量或配置值在多处各自定义
- 完全相同的测试用例
- 所有调用点都传同一个值的形参
- 逻辑等价但写法不同的代码
- 同一事实的两种表示（见 `references/state-space.md`）

## 复杂度

- 单函数是否装着两个以上可以各自独立命名、独立测试的职责
- 类型是否大到一个使用场景同时用得上它的全部字段
- 参数是否多到无法从调用点看出哪个是哪个
- 布尔参数把函数劈成分支
- 嵌套过深、单个条件表达式过于复杂
- 循环内每次迭代都不变、却被反复计算的表达式
- 无副作用且结果未被使用的表达式

## 表达

- 命名不含业务语义，或语义与行为不符
- 注释写的意图与代码现在的行为已经不符（陈旧注释）；只写意图、且与行为一致的注释不在此列
- 用基本类型承载有业务含义的值，字面量散落在代码里而没有名字
- 冗余的类型标注，以及可以从其他字段推导出来的冗余字段

## 候选生成器（只回答"先看哪几处"）

- 冗余：空函数体与只做一行的透传层（扫函数体）、只被一处引用的类型／只有一个实现的抽象（扫引用数）、注释掉的旧代码（扫连续注释行）、所有调用点都传同一值的形参（扫调用点）
- 表达：注释与相邻代码的改动不同步（陈旧注释）、基本类型承载业务值（基本类型形参名带领域词）
- 复杂度：参数个数、`bool` 形参、嵌套深度、循环体内不随迭代变化的表达式
