**这一册判的是一件事：代码里「写着的」与「实际会发生的」是不是同一份。** 声明在、没人用（死代码）；路径在、走不到（不可达）；同一件事被做了两遍（冗余、重复）；一处装着几件互不相干的事（复杂度）；名字或注释说的与做的不符（表达）——都是这两份对不上。所以判据不在条目里，在这一句：**这段代码声称的那件事，有什么东西能证明它真的成立？** 证明不了、或者证明它的东西与声称它的东西是两处，就是这一册要找的。**常见形态在 `references/code/known.md`：判据在上，形态是召回，不是全集。**

对着代码本身逐条问，每条只要出现一次真实命中就够。

如果手上拿到的是一个补丁而不是完整实现，用 `references/diff.md`，它会按变更逐块走，并调用本件判断死代码与冗余。

**先分清这一册里哪几节有仪器、哪几节只有候选生成器。** **死代码有仪器**——编译器与测试；**不可达也有仪器**——编译器对不可达代码与恒真比较的告警；**重复有半个**——字符串比对能穷举"同一表示"，判不了"逻辑等价"（见「判据」里的重复）。**冗余、复杂度、表达三节没有仪器，只有候选生成器**（扫什么见 `references/code/known.md` 的「候选生成器」）。**候选生成器只回答"先看哪几处"，不回答"这里是不是问题"。这几节漏掉了不会有人告诉你**——结论挂依据时要如实标，别拿"编译器是绿的"当独立依据。

**机器生成物与 vendored 第三方代码不按这一册判。** 生成代码的坏味道密度按设计就高，逐条问会整片命中——那不是在报问题，是在报生成器。对它们只判两件事：**来源**（`vendor/`／`third_party/`／`generated/`、文件头 "DO NOT EDIT"、"@generated"、与锁定版本一致的哈希）和**再生成流程**（能不能从生成器重跑出来、手改会不会被下次生成覆盖）。判不出来的，报"来源不明"，不要报"重复"。

**对象是代码实现或变更集 → `references/adversarial.md` 必载，这里没有判断。** 再动**不可逆状态**就再叠 `references/verification.md`；**改动或对象落在测试、夹具、验证脚本或构建配置上时也必载**——那几类代码的失败通常不置退出码，缺了这一册，这一面会读成"没有问题"；语言与界面栈的判据不在这几册里：认得出这个栈、且它有清单，`references/lang/〈栈名〉.md` 必载；**认不出是什么栈，与没有清单是同一件事**，都走 `references/lang/method.md` 现场推——**「认不出」不是「不必判」**。**改动碰了外部输入、性能敏感路径、部署与回退，或碰上“这里一直靠重试／人工步骤维持”时**，按 `references/security.md`、`references/performance.md`、`references/operability.md`、`references/robustness.md` 判——看不出涉不涉及，就读那一册的开头两段再定，别凭“不像是安全问题”跳过。**开工时把这一次要加载的册写一行**（`加载：adversarial、verification、lang/rust`），与账本放在一起，交报告时抄进去。**报告里没说 adversarial 那一面查过还是没查，就不算查过。** 对象可以是一整份实现，也可以只是目录／模块切片：切到的操作按本册问，没切的写进覆盖表。每条结论怎么交代来源与后果，按 `references/contract.md` 第一、二节。

**多片合起来看时，先列一行维度。** 对象是多个文件、或已被切成几片分给别人时，先照 `references/state-space.md` 的维度清单列一行——它是镜头，不是你交付的那份；结论仍按本册逐条写。

**对象带持久化状态、恢复路径、多个写者、或同一事实有两种表示时，`references/state-space.md` 必载，且要在读代码之前读**——先写基线、不变量与维度，再拿代码去对。**范围判不出来时，先读 `references/derive.md` 冻结范围**，再读文件。

**对象大到一路握不住时，先分路再读**。切法与阈值在 `references/contract/process.md`；**按保证切，不按文件族切**。

**对象是界面代码时，先跑一遍探测。** 按 `references/theme/method.md` 的探测顺序看项目声明了哪套规格——没有声明就不读 `theme/` 下的任何一册；"拿不准"不是理由，探测顺序就是把拿不准变成判得出的东西。

## 判据

- **规格**：**对象声称的效力本身也是被审对象**——规格与代码之间也是一对「写着的」与「实际会发生的」。三种形态都在这对东西之间显形：同一约束在两处写成两种；规格与测试互相矛盾（**两边自洽正是照着同一个误解写出来的标记**）；两句话各自要求的验收条件不能同时成立。**判据：按其中一句做，另一句就做不到**——说得出来，报的是规格本身（哪两句、在哪一步互相拆台），不是这两处各自的实现；说不出来说明还没读出来，不要报「需求不清」。规格没写或写得含糊时同理：**不要替它挑一个合理解释继续往下走**，把「缺的是哪一句、它挡住哪几条判断」写进缺口。
- **死代码**：仪器是编译器与测试，不是搜索——删掉或改名后编译，"未使用的导入""找不到该名称"就是消费点清单。隐式派发族（格式化占位、错误传播、迭代与推导、析构、运算符重载、反射或注册表）要跳过搜索：消费点与声明处在源码文本上零关联，唯一权威判据是编译或运行一次。**参数、配置项、返回字段同理**：解析了却没有消费者，与"声明了没人用"是同一种——判据也一样，看有没有东西因它而变；接收了不生效比拒绝更贵，调用方会以为它已经生效。
- **不可达**：代价不是浪费几行，是**它看起来在被维护**。判法不是看像不像，而是把它固定到你认为「它取不到」的那一侧，还编得过、还跑得到吗。跑得到说明你关于"取不到"的假设错了——那本身就是一条发现。
- **冗余**：上下文已保证安全的前提下仍重复做的空值或边界检查。**判据：与前一次检查在同一个函数体内 ＋ 中间没有任何可能改变被检值的语句**；两者同时成立才算，**距离本身不是判据**；跨了函数、模块、进程或持久化边界的一律不报——那是纵深防御；**边界上的检查永远不冗余**。
- **重复**：**同一份东西在两处各自写死、而它们本该是同一份**。先用字符串比对列出候选对（同一字面量出现在 ≥2 处、同一文案两种措辞、同一正则抄了两份、同一组参数在多个调用点传同一个值），再逐对判等价；语义等价没有仪器，只能用结构线索逼近。**报之前写一句你用了哪一种线索、覆盖到哪**——不写，读者分不清"没找到"与"没找"。**现在没有症状不是不报的理由**：重复的代价落在下一次——同一份东西被改在一处、另一处不知情，而漏掉的那一处不会报错。报的时候把那一步写出来（哪个位置会因为这份重复，在以后的哪类改动里被漏掉），读者据此自己判要不要现在动。同一份输入在两个位置各算一遍时，判据是"这份值有没有唯一的产生点"。同一判据的两处实现且处置相反（一处上抛、一处吞掉）：那不是重复劳动，按 `references/contract.md` 第三节把两处原文都写出来。
- **复杂度**：代价不在行数，在**要动几处才能保持一致**。问法是：**不读函数体，说得出它做什么吗；改一处，要不要跟着改别处？** 两个都答得顺，就不报——难读但不是缺陷的东西不欠你一个重构。
- **表达**：名字与注释说的要和做的一致。**跨函数承诺**（"与 `X` 同一口径""这由 `X` 处理"）先去被引用处核对是否仍为真，再判它靠什么承重——指不出承重物的，报"缺承重物"，不要报"注释冗余"：它的问题是两处必须同时改、而第二处不会报警。**「论证式注释」**的保留判据：删掉它，后人会不会做出错误决定。**同一实体的字段与枚举能不能组合出无意义的状态**？能构造出来就是下一条路径会踩到的 bug；**判据是能不能被类型或构造函数挡住**——「注释里写了不要这么用」不算挡住。**注释里关于世界的断言，要能指到它的依据**：某个符号在哪个版本或平台上存在、某个数的单位与量纲、某条前置条件的次序、某个常量的规范出处、某一支是否真的可达——指不到的按"没人验过的断言"报，它比过时注释更贵，因为下一个改代码的人会照它改。**同一字段在两处按不同单位读写**是这一族的特例：名字与类型都不带单位时，错的不是那一行，是一年后按另一种单位读它的那处。
- **跨模块**：循环依赖、跨边界重复维护同一信息、不必要的间接层、重复实现的横切关注点，归属 `references/architecture.md`；"冗余但先留着"的，保留的一方要给出理由。

**手上出现这些材料时，去 `references/code/known.md` 取对应的已知形态**（它列的是常见形态，不是判据，也不是全集）：改动落在编译产物、日志、依赖清单里 → 死代码、不可达；手上有规格、需求或验收条件，而代码与它逐条对不上 → 规格；同一个字面量／文案／正则／参数值在多处出现 → 重复；不读函数体说不清它在做什么 → 复杂度；注释与代码的行为对不上，或字段之间能拼出无意义的状态 → 表达；有检查写了第二遍 → 冗余。
