## 先划界

- 本册问的是"**Go 的机制让这个缺陷怎么发生**"。goroutine 泄漏、循环里的 `defer`、`Timer`/`Ticker` 不 `Stop` 这些**同时也是失败路径**，`review` 的 `robustness.md` 会从"出事之后会怎样"那一侧再问一遍（它的「资源与规模」与「生命周期耦合」两节）。同一处两边都可能命中：**报一处，说清是按哪条判的**，不要两册各报一遍。
- `defer` 的**清理顺序与成对性**属于生命周期，归 `robustness.md`；本册只管 `defer` 本身的语义（参数求值时机、具名返回值被改写、`os.Exit` 不执行 `defer`）。

## 先跑工具链，工具链报的不写进本件

`go vet ./...` 默认跑全部检查；当前集合用 `go tool vet help` 查。与本册边界相关的是这批（分析器名对照 Go 1.27）：`copylocks`（按值传含锁的类型）、`lostcancel`（`cancel` 没调）、`waitgroup`（`Add` 写在 `go func` 内部，与 `Wait` 形成竞态）、`loopclosure`、`errorsas`（传给 `errors.As` 的不是非 nil 指针或非 error）、`printf` / `slog`（格式串与结构化日志调用）、`unsafeptr`（`uintptr` 与 `unsafe.Pointer` 的非法转换）、`unusedresult`、`cgocall`（部分 cgo 指针传递规则）、`unreachable`、`structtag`、`stdversion`、`testinggoroutine`、`httpresponse`。注意 `unusedresult` 只覆盖它清单内的函数，不是"任何被丢弃的返回值"。

`staticcheck ./...` 覆盖 `SA` / `S` / `ST` / `QF` 四族规则，与 vet 重叠的部分以它为准；它报的一律不写进本册。

`errcheck ./...`（或 `golangci-lint run`）覆盖未检查的错误。

`go build` / `go test` 自己就报的同样不列：未使用变量、未使用导入、循环导入、`gofmt` 格式问题。

`go test -race ./...` 只覆盖**实际跑到**的路径。跑到的那条不写；测试覆盖不到的并发路径上的竞争仍要写。

## 错误处理

- 用 `==` / `!=` 直接比较错误值而不是 `errors.Is`：被 `%w` 包装过之后比较静默失效。不报：比较双方都是包内哨兵，且注释声明了不会被包装
- `fmt.Errorf` 只用 `%v`/`%s` 不加 `%w`，错误链在这一层断掉。不报：刻意截断以免向外泄露内部错误类型
- 哨兵错误就地 `errors.New` 而不提成包级 `var ErrXxx`，调用方无法用 `errors.Is` 匹配。不报：该错误只在包内消费
- 自定义错误类型没有 `Unwrap`（错误链）或 `Is`/`As`（自比较），调用方只能靠字符串匹配。不报：该类型不向外暴露，或调用方不需要匹配
- 用 `string` 当错误类型，或经一次 `err.Error()` 转换：原始类型与结构化上下文在这一层再也拿不回来。不报：仅用于日志或展示
- 同一错误类型的转换散落在多处手写，没有统一到 `Unwrap`/`Is`/`As` 或包级构造函数。判据：把每一处**逐一点名**列出——检索命中只说明"存在"，空结果只说明"未发现"，不是"没有"
- 库代码里把**调用方传入的参数**会触发的可恢复错误处理成 `panic`——把调用方的问题变成它自己的崩溃。正当例外：`init`、违反内部不变量、测试代码

## 资源与 defer

- `defer` 写在循环体内：句柄要到函数返回才释放，循环量一大就泄漏。不报：循环次数确定且小、函数体短
- 打开的资源（`os.File`、`net.Conn`、`http.Response.Body`、`sql.Rows`）只在正常路径上关，错误路径漏关
- `resp.Body.Close()` 之前没把 body 读完（`io.Copy(io.Discard, …)`），连接无法复用。不报：一次性连接，或明确不再复用
- `time.Timer` / `time.Ticker` 不 `Stop()`，把回收留给 GC。不报：一次性 `Timer` 已触发，或 `Ticker` 随进程退出
- 循环里用 `time.After`：每轮新建 timer，直到触发才回收，长循环会积累
- `cancel` 在循环内 `defer`：每个都拖到函数返回才调，积累到退出。不报：循环次数确定且小——**但 `go vet` 的 `lostcancel` 只看"调没调"，不看"什么时候调"**，所以这条要自己判
- 用 `runtime.SetFinalizer` 代替 `Close`，而不是当最后一道防线
- `os.Exit` / `runtime.Goexit` 不执行 `defer`，依赖 defer 的清理不会发生。不报：退出前已显式清理
- `defer` 改写具名返回值（`func f() (err error) { defer func() { err = … }() }`）：调用方看到的返回值被悄悄换掉
- `defer f(x)` 的参数在 defer 语句处求值，`defer func() { … x … }()` 捕获的是引用——两者语义不同，混用会取到错的值

## panic 与 recover

- `recover()` 不在 `defer` 里调用——此时必然拿到 nil
- 非主 goroutine 里 panic 没有 `recover`，整个进程被带走。不报：该 goroutine 的 panic 即预期退出，且已文档声明
- `recover` 吞掉 panic 后既不记录也不重抛，把 bug 变成静默错误。不报：panic 本身是预期信号，且已记录
- 用 panic/recover 做控制流（自己实现 `try`、拿它当正常跳转）
- 库代码用 `panic` 传播可恢复错误，调用方无法预期。不报：文档已把 panic 写成契约

## 并发与 context

- 起出去的 goroutine 没有退出路径（无 ctx、无 close 信号、无返回通道），父函数一返回就泄漏。不报：进程生命周期内的后台单例——此时要在契约里写明它不退出
- `select` 里没有 `ctx.Done()` 分支，取消信号到不了这个 goroutine。不报：该 goroutine 由 `close(channel)` 单独控制
- 向已关闭的 channel 发送，或关闭一个仍可能有发送方的 channel
- 从关闭的 channel 读值不检查第二返回值 `ok`，把零值当有效数据。不报：零值就是该 channel 的有效值，且已文档声明
- `for v := range ch` 迭代 channel：不关闭就永久阻塞，而且这个循环**无法被 ctx 取消**。不报：契约保证发送方必然 close
- 无缓冲 channel 当同步用，发送/接收方都没有超时或取消，一处不到就永久阻塞。不报：契约保证对端必然到达
- `select` 里只有 `default` 做忙轮询，空转 CPU
- 共享 map 并发读写。`-race` 只覆盖跑到的那条路径，覆盖不到的仍要写
- `context.Context` 存进 struct 字段或全局变量，而不是当第一个参数一路传下去
- `context.WithValue` 存业务参数或可选配置——调用方无法从签名得知，取值还要断言。不报：确实是请求域元数据（trace id、身份），且 key 类型私有
- **取消安全**：`errgroup` / 自建 worker 里的 goroutine 被取消时，**已经写了一半的输出、已释放的锁、已发出的消息**由谁收拾。拿不出结论的，就把每个 goroutine 的取消语义写成契约（谁能取消、取消后系统处于什么状态），别留给调用方猜

## 接口与类型

- 值接收者方法里改字段（改的是副本），调用方看不到——编译器不报。不报：字段是 slice / map / chan / 指针，改的是它指向的东西
- 方法集分叉：`T` 只有值接收者方法，`*T` 含全部，接口实现判断就在这处分叉。用 `*T` 实现接口之后又在调用点传 `T`，编译能过而运行时不匹配
- 接口零值（`var x SomeInterface`）调方法 panic。不报：零值有文档定义的语义
- 类型断言没检查 `ok`，类型不符时直接 panic（非错误的类型断言不在 `errorsas` 覆盖内）
- 接口值比较时动态类型不可比较，运行期 panic。不报：两侧动态类型在编译期已知
- 把 `*T` 赋给 `any` 之后与 `nil` 比较：`var p *T; var i any = p; i != nil` 为真，与直觉相反
- 导出的类型里嵌了未导出的字段或类型，外部既无法构造也无法读取。不报：本来就只允许经构造函数创建，且已提供

## 泛型

- 用 `any` + 类型断言的地方本可以写成泛型，把类型错误从编译期推到运行期。不报：类型集合确实开放（由插件或配置驱动）
- 约束写成 `any`，实现体里却还要对类型参数做断言或反射——约束没表达真实约束。不报：约束来自外部库，改不了
- 想按具体类型分派，于是类型参数只能经 `any` 中转再断言——这时约束选错了。不报：分派本来就要在运行期做
- `comparable` 约束不覆盖含 `slice`/`map`/`func` 字段的 struct，`map[T]…` 拿它做键会运行期 panic。不报：键类型是具体类型而不是类型参数
- 类型参数的零值与可比较性取决于约束：接口约束下 `T` 是接口类型，`var t T` 调方法 panic、`t == zero` 可能 panic，与具体类型实例化时行为不同。不报：约束是可比较的具体类型

## 切片、map 与字符串

- `append` 到与他人共享底层数组的切片，两处互相踩——常见于把子切片传出去之后再 `append`
- `s[i:j]` 截出来的切片**保留整个底层数组**，小段数据把大块内存一起钉住
- `len(s) == 0` 与 `s == nil` 混用：JSON 序列化出 `[]` 还是 `null` 由它决定
- `nil` map 写入 panic
- `for range` 里取 `&v` 并保存：1.22 之前所有指针指向同一地址；1.22 起每轮是新变量，但**有意共享**时仍要显式拷贝。版本以 `go.mod` 的 `go` 指令为准，别凭印象
- 循环里用 `+=` 拼字符串，每次都重新分配。不报：循环次数确定且小
- `string` 与 `[]byte` 互转总是拷贝；`unsafe.String` / `unsafe.SliceData` 是零拷贝路径，用错会破坏字符串的不可变性
- 迭代 map 时依赖顺序，或者把顺序写进测试

## unsafe、cgo 与 reflect

- `unsafe.Pointer` 与 `uintptr` 互转之后跨越 GC 点使用——对象可能已被移动或回收
- `//go:linkname` 挂到运行时或别的包的未导出符号，且没有注释说明为什么不能用公共 API
- cgo 传进来的 Go 指针被 C 侧长期保存，违反 cgo 指针规则（`cgocall` 只静态看得到一部分）
- `unsafe` 调用覆盖了并不需要它的语句，把安全代码也划进了审计范围
- 类型集合编译期已知、本可用类型参数或接口表达，却仍在运行期用 `reflect` 做类型分派

## 可见性与包

- 为了测试而导出的标识符用了大写开头，而不是同包 `_test.go` 或 `export_test.go`。不报：外部包测试必须导出
- 导出类型把内部类型当字段或参数暴露，下游既无法构造也无法读取。不报：内部类型本身是已文档化的接口
- 导出的包级变量，外部可以改写内部状态。不报：它是只读哨兵或错误值

## 构建与依赖

- `go.mod` 里 `require` 了但代码没有任何引用（`go mod tidy` 只能清一部分）。不报：间接依赖，或 `tools.go` 一类的工具依赖
- `replace` 指向本地路径，别人克隆下来构建失败。不报：仓库文档写明了这是开发用途，发布不经过它
- 依赖的 import path 指向 fork，而没有注释说明为什么用 fork。不报：仓库文档已写明
- `init()` 里发网络请求、起 goroutine、读环境或文件——`init` 没有错误返回路径，错误只能吞掉或 panic，测试也没法重置。不报：`init` 只做纯计算或变量初始化
