## 错误处理与退出码

- `set -e` 在以下上下文中不生效：`if`/`while` 条件、`&&`/`||` 链中非最后一条、`!` 取反、命令替换内、子 shell 内。不报：脚本已逐处显式检查退出码，或该命令的失败在业务上可接受
- `set -e` 与管道：默认只有最后一条命令的退出码参与判断，前段失败被忽略。不报：已设置 `set -o pipefail`
- `set -u` 对 `"$@"` 在无参数时仍安全；对 `"${arr[@]}"` 在空数组时，Bash ≤ 4.3 报 "unbound variable"，Bash ≥ 4.4 不再报错（本册在 Bash 5.3 上实测：不报），行为随版本变化。不报：已在引用前检查数组非空，或已确认运行环境版本
- 函数返回码取自最后一条命令，中间失败被后续成功命令覆盖。不报：函数已显式 `return` 或最后一条命令即判断依据
- `$?` 在 `if`、`while`、`!` 求值后被覆盖，后续读取拿到的是条件判断本身的退出码。不报：`$?` 在命令后立即读取，无中间语句
- `(( i++ ))` 在 `i=0` 时返回退出码 1，被 `set -e` 视为失败并**终止脚本**（本册在 Bash 5.3 上实测：后续语句不再执行）。不报：表达式有意用 `(( ++i ))` 或已处理该退出码
- `local` 与声明同行的命令替换：`local x=$(false)` 之后 `$?` 是 `local` 自己的 0，**被替换命令的失败被吞掉**（本册在 Bash 5.3 上实测）。不报：声明与赋值分开写，或单独检查赋值结果

## 引用与展开

- `"$@"` 与 `"$*"` 语义不同：前者每个参数独立一项，后者用 `IFS` 首字符拼接。不报：使用意图与选择一致，且已在文档中声明
- `"${arr[@]}"` 与 `"${arr[*]}"` 同上。不报：同上
- `[[ ]]` 中 `==` 做模式匹配（右侧 glob），`=~` 做正则匹配；写成 `[ ]` 时 `==` 是字符串比较。不报：比较双方类型与语义已显式声明
- `${var:-default}` 与 `${var-default}` 在 `var` 为空字符串时行为不同：前者用默认值，后者用空串（Bash 5.3 实测）。不报：已明确变量的可能状态
- `${var#pattern}` 与 `${var##pattern}`、`${var%pattern}` 与 `${var%%pattern}` 的最短/最长匹配方向相反。不报：模式已保证唯一匹配
- `IFS` 被修改后影响 `read`、`$*` 展开、`for` 循环分词，未恢复导致后续代码行为异常。不报：`IFS` 修改限于局部作用域或已恢复
- `[ ]` 里的 `<`、`>` **是重定向不是比较**：`[ a < b ]` 会去读文件 `b`（Bash 5.3 实测报 `b: No such file or directory`），要比较得用 `[[ a < b ]]`。不报：已统一使用 `[[ ]]`，或已显式转义

## 子 shell 与作用域

- 管道中每个命令在子 shell 中执行，`while read` 循环内的变量赋值不保留到管道外（Bash 5.3 实测：循环后仍是循环前的值）。不报：已使用进程替换 `< <(...)` 或 `shopt -s lastpipe` 让最后一段在当前 shell 执行
- `$(...)` 内的变量赋值不保留到调用方。不报：有意隔离，或通过输出回传
- `local` 变量在函数返回时丢失，但若同名的全局变量存在，函数内读取到的是 local 值，调用方仍看到全局值。不报：变量名在作用域内唯一，无遮蔽
- `declare` 在函数内默认创建 local 变量，在函数外创建 global 变量；同一写法在两处语义不同。不报：声明位置已明确
- `source` 或 `.` 加载的文件在当前 shell 中执行，其中定义的变量和函数污染调用方命名空间。不报：被 source 文件已文档声明其副作用

## 算术与整数

- Bash 算术使用有符号 64 位整数，溢出回绕为负数，不报错（Bash 5.3 实测：`9223372036854775807 + 1` → `-9223372036854775808`）。不报：参与运算的量在源码里可见（常量、`wc -l` 一类小上界），且不涉及外部输入或跨平台序列化
- `$(( ))` 中前导零的数字被解释为八进制（`010` 为 8；`08` 直接报 `value too great for base`。Bash 5.3 实测）。不报：数字已用 `10#` 前缀强制十进制
- 除零导致 `$(( ))` 报错并可能触发脚本终止。不报：除数已检查非零
- 算术展开中引用未定义变量不报错，视为 0。不报：`set -u` 生效，或变量已声明
- `let` 与 `(( ))` 在参数求值顺序和退出码上行为不同。不报：使用一致，不混用

## 数组

- 稀疏数组中 `${#arr[@]}` 返回元素个数，不是最大索引 +1；`${arr[@]:1:2}` 按元素顺序切片，不是索引范围。不报：数组已保证连续
- 未 `declare -A` 的关联数组被当作索引数组，键被当作算术表达式求值。不报：已显式 `declare -A`
- `arr[0]` 与 `${arr[0]}` 在部分上下文中行为不同，前者可能被当作命令名。不报：数组下标访问已用 `${...}` 包裹
- `unset arr` 删除整个数组，`unset arr[0]` 删除一个元素；后者在稀疏数组中留下空洞，`${#arr[@]}` 仍递减但索引不连续。不报：访问方式已处理稀疏

## 条件判断

- `[ ]` 是命令，`[[ ]]` 是语法；前者中未加引号的变量若为空或含空格，`-eq` 等运算符两侧表达式被拆错。不报：`[ ]` 中已加引号
- `[[ ]]` 中 `&&`、`||` 短路求值；`[ ]` 中 `-a`、`-o` 不短路，两侧均被求值。不报：两侧无副作用
- `[[ -e $path ]]` 对符号链接指向的悬垂目标返回假，`-L` 只看链接本身是否存在。不报：已按具体需求选择测试运算符
- `case` 中 `;;` 与 `;&`、`;;&` 的贯穿行为不同。不报：分支已用 `;;` 终止，无有意贯穿
- `[[ $x =~ pattern ]]` 中正则未加引号，若 `pattern` 含空格则被拆分。不报：正则已存入变量并作为整体引用
- `until cmd` 与 `while ! cmd` 的退出码方向相反：`until` 在 `cmd` 成功时终止，`while !` 在 `cmd` 成功时继续；两者互换会导致循环提前终止或滞后终止。不报：使用意图与所选循环一致，且无互换

## 管道与重定向

- `cmd > file 2>&1` 与 `cmd 2>&1 > file` 语义不同：前者 stdout 与 stderr 都进 file，后者 stderr 进原 stdout、stdout 进 file。不报：重定向顺序已按意图排列
- 循环中 `> file` 每次迭代截断文件，只保留最后一次输出。不报：已用 `>>` 或循环外统一重定向
- 管道中 `read` 的退出码来自最后一条命令，读入的数据量不被反馈。不报：已检查读入计数或使用 `read -r` 后检查
- 进程替换 `<(...)` 的退出码不被父 shell 检查，其中命令失败静默忽略。不报：已显式收集进程替换的退出码
- 管道中前段命令收到 SIGPIPE 时的退出码（141，Bash 5.3 实测 `PIPESTATUS[0]=141`）不被 `set -e` 特殊处理，被当作失败。不报：已显式忽略该退出码，或上游已处理 SIGPIPE

## 信号与 trap

- `trap` 在非交互 shell 中对未捕获信号的处理依赖父进程继承，行为不确定。不报：脚本启动时已显式 `trap` 关键信号
- `trap` 在子 shell 中**不继承**，父 shell 设置的清理逻辑在子 shell 中不执行（Bash 5.3 实测：子 shell 退出时父的 `EXIT` trap 不触发）。不报：子 shell 已显式重新设置 trap，或清理逻辑在父 shell 的 `EXIT` 中统一处理
- `trap ... ERR` 只在 `set -E` 时对函数和子 shell 中的失败生效。不报：已设置 `set -E` 或有意不覆盖子 shell
- `trap` 命令在信号处理期间若再次收到同一信号，默认被阻塞直到处理完成。不报：处理逻辑幂等，或已显式解除阻塞
- `kill` 发送 SIGTERM 时，被调用进程若在 `trap` 中未显式退出，信号处理后继续执行。不报：`trap` 处理中已显式 `exit`

## 字符串操作

- `${var//pattern/replacement}` 中 `pattern` 是 glob，不是正则；`*`、`?`、`[...]` 行为与正则不同。不报：模式已按 glob 语法书写，或已改用 `sed`/`awk`
- `${var:offset:length}` 中 `offset` 为负时需加空格 `${var: -1}`，否则被解析为默认值语法（Bash 5.3 实测：`v=abc` 时 `${v: -1}` 得 `c`、`${v:-1}` 得 `abc`）。不报：偏移已保证非负
- `${!var}` 间接引用中 `var` 的内容被当作变量名再次求值；`eval` 同理。输入可控时构成注入。不报：变量名或待求值文本来自脚本内常量，无外部输入
- 命令替换 `$(...)` 去除尾部换行，若输出结尾的换行有意义则被静默截断（Bash 5.3 实测：`a\n\n` 取回只剩 1 字符）。不报：已用其他方式保留换行，或输出本身无尾部换行
- `${var^^}`、`${var,,}` 的大小写转换受 `LC_CTYPE` 影响，不同 locale 下结果不同。不报：已显式设置 `LC_CTYPE=C` 或有意依赖 locale

## 循环与迭代

- `while read -r line; do ...; done < file` 里 **`-r` 恰恰会关掉续行**：默认模式下 `<反斜杠><换行>` 被当作续行（两行并作一行读入），加了 `-r` 之后反斜杠不再特殊，**每一行就是一行**（POSIX `read`：`-r` "Do not treat a `<backslash>` character in any special way"）。同一段代码在别处若**没加** `-r`，遇到以反斜杠结尾的行就会把两行粘成一条。不报：输入来自机器生成、已保证行尾无反斜杠
- `for f in *` 在目录为空时展开为字面量 `*`，循环执行一次（Bash 5.3 实测：`GOT=/tmp/.../*`）。不报：已用 `shopt -s nullglob` 或已检查展开结果
