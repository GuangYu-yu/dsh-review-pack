## 先跑工具链，工具链报的不写进本件

`-Wall -Wextra -Werror` 覆盖：未使用变量、格式串不匹配、有符号/无符号比较、返回局部变量地址。

部分编译器在 `-Wall` 或显式 `-Wnon-virtual-dtor` 下覆盖非虚析构函数；部分编译器在 `-Wdelete-non-virtual-dtor` 下覆盖通过非虚析构基类指针删除。

`-fsanitize=address,undefined`（ASan+UBSan）覆盖**跑到路径上**的：数组越界、use-after-free、双重释放、有符号整数溢出、移位量过大、空指针解引用、对齐、`new[]`/`delete` 不匹配。

`-fsanitize=memory`（MSan）覆盖跑到路径上的未初始化读取。

`-fsanitize=thread`（TSan）覆盖跑到路径上的数据竞争。

`clang-tidy` 覆盖：`explicit` 缺失、`modernize-*`、`bugprone-*`、部分生命周期与 ODR 问题。

`cppcheck` / MSVC `/analyze` 覆盖部分资源泄漏、模板实例化问题、死代码。

前提是它真的跑过：CI 里没有这一步时，先自己跑一遍，或先把它接进 CI。

## 指针与引用

- 返回指向栈上局部变量的指针或引用，经中间变量时不报。不报：返回值已按生命周期标注（`[[clang::lifetimebound]]`）且调用方在表达式内消费
- 悬垂引用/视图：`std::string_view`/`std::span`/`std::reference_wrapper` 比其所有者活得久；或 lambda 按引用、按 `this` 捕获后逃逸到所有者生命周期之外。ASan 不总报；C++20 起 `-Wdangling` 部分覆盖但需显式开启。不报：视图或闭包的生命周期已由调用方在同一表达式或同一作用域内约束，且已文档声明
- 指针算术越过数组末尾后再解引用：跨对象场景 ASan 不总报。不报：单元素数组取尾后指针仅用于比较
- `memcpy`/`std::copy` 源与目标重叠（应使用 `memmove`/`std::copy_backward`）。不报：源与目标已证明不重叠
- 严格别名：对象具有已声明类型，却以不相关类型左值访问。不报：经 `char*`/`std::byte*` 访问任意对象
- `reinterpret_cast` 后按类型使用对象，绕过类型系统。不报：在相同类型或标准布局兼容类型之间转换
- `const` 对象被 `const_cast` 后修改，底层对象确实为 const 时 UB。不报：底层对象本身非 const，`const_cast` 只是恢复可写性
- 对 `union` 的成员写入后读另一个成员，类型双关语义实现定义。不报：已用 `std::memcpy` 或 `std::bit_cast` 做双关
- 空指针解引用（UBSan 只覆盖跑到路径）。不报：引用类型保证非空、或指针已文档声明非空
- 数组越界访问（ASan 只覆盖跑到路径）。不报：下标已受约束
- 解引用 `end()` 迭代器，或对失效迭代器操作（ASan 不总报）。不报：迭代器在容器未修改的作用域内使用

## 内存与生命周期

- 裸 `new` 后，在异常或提前返回路径上没有 `delete`——每条返回路径都要过一遍。不报：已用 RAII 包装
- `delete` 后继续用同一指针，或同一指针被 `delete` 两次（ASan 只覆盖跑到路径）。不报：析构后立即置 `nullptr`，且此后再无解引用
- 未初始化成员变量读取（MSan 需单独构建，`-Wall` 只覆盖一部分）。不报：构造函数初始化列表中必然已赋值
- 对齐违规（UBSan 只覆盖跑到路径）。不报：已用 `alignas` 或 `std::launder` 配合正确对齐
- 成员自身的构造函数抛异常，该成员未被完全构造，其析构不会被调用，已构造的兄弟成员会被销毁。不报：成员均为 RAII 类型，构造失败后已获取资源由已构造成员的析构负责释放
- 移动后的对象仍被使用（有效但未指定状态）。不报：对象已重新赋值或已销毁
- 引用成员或 const 成员导致赋值运算符被删除，却仍尝试拷贝赋值。不报：类型显式删除了赋值运算符且调用方不依赖赋值
- 通过基类指针 `delete` 派生对象，而基类析构非虚（`-Wnon-virtual-dtor` 不总报）。不报：基类析构已声明 virtual，或已声明 protected 非虚
- `shared_ptr` 互相持有形成循环，析构不触发。不报：已用 `weak_ptr` 打破环
- `unique_ptr`/`shared_ptr` 与裸指针混用，所有权不清晰。不报：裸指针仅作观察者，且所有者已文档声明
- 对象切片：按值传递派生类给基类参数，派生部分被截断。不报：基类已声明不可拷贝，或调用点明确按基类视图处理
- 静态初始化顺序（SIOF）：跨翻译单元的全局对象在对方构造前被使用，读到的可能是零初始化值。不报：已改用 Meyers singleton、`constinit`，或所有跨单元访问均发生在 `main` 之后

## 整数与转换

- 有符号整数溢出（UBSan 只覆盖跑到路径）。不报：编译期已证明值域
- 移位量 ≥ 类型宽度，或对负数左移。不报：移位量已受约束
- `int` 与 `size_t`/`unsigned` 隐式转换发生在赋值、返回、作为下标处（`-Wsign-compare` 只覆盖比较）。不报：值域已证明非负
- `int64_t` → `int32_t` 窄化截断，`-Wconversion` 不总报。不报：值域已证明在目标范围内
- `char` 的符号性平台依赖。不报：显式使用 `signed char`/`unsigned char`
- 浮点到整数转换溢出。不报：已检查范围，或使用 `std::lround`/`std::clamp`
- 枚举值隐式转换到整数后丢失符号。不报：枚举已声明底层类型

## 求值顺序

- 在 sequenced-before 关系之间多次修改同一变量。不报：不涉及共享可写状态

## 异常与错误处理

- 异常按值捕获（`catch (std::exception e)`）导致切片，应按引用捕获。不报：按值捕获的是 `std::exception_ptr`
- `throw()` 或 `noexcept` 与实际抛出不符。不报：函数体内确实不抛，或已用 `noexcept(false)` 显式声明
- 析构函数中抛异常导致 `std::terminate`。不报：析构函数声明 `noexcept` 且实现不抛
- 异常在 `catch` 中重抛丢失原始类型（`throw e;` 而非 `throw;`）。不报：捕获的是值类型且无多态
- `setjmp`/`longjmp` 跨越 C++ 栈展开，析构函数不执行。不报：跳转目标不持有 C++ 对象
- 同一函数里同时存在 `std::error_code`/`std::expected` 返回与抛出异常两条错误路径，或同一调用层既 `catch` 又查 `ec`。不报：已按层划清错误传播方式并文档声明
- `std::expected` 的 `value()` 在错误状态下调用，抛 `bad_expected_access` 而非返回错误码，调用方以为在走错误分支。不报：调用前已检查 `has_value()`，或使用 `value_or`

## 类型与继承

- 构造函数/析构函数中调用虚函数，或虚基类构造/析构期间调用虚函数，不分派到派生类。不报：调用的是非虚成员
- 多重继承菱形问题未用虚继承。不报：继承层次中无共同基类
- 拷贝构造/赋值运算符未处理自赋值。不报：已用 copy-and-swap 或成员均自赋值安全
- 虚函数在派生类中签名不匹配，未标注 `override` 时静默隐藏基类版本。不报：所有覆写均已显式标注 `override`，签名不匹配由编译器报错
- 移动构造/移动赋值未标记 `noexcept`，导致容器扩容退化为拷贝。不报：类型本身不可移动，或明确接受退化

## 模板

- 模板定义在 `.cpp` 里导致链接错误。不报：所有使用点均在当前翻译单元，或已在 `.cpp` 中显式实例化且实例化声明在使用点可见
- 模板特化在某编译单元可见、另一单元不可见，ODR 违规。不报：特化定义在头文件中，且所有实例化点所在翻译单元都包含该头文件
- 模板参数依赖名称的 `typename`/`template` 缺失，编译器不总报。不报：该名称已被编译器判定为非依赖名称
- SFINAE 或 `if constexpr` 分支中对不支持的类型实例化。不报：该分支对当前模板参数集合已证明可实例化，或已被 `requires`/`static_assert` 显式排除
- 显式实例化与隐式实例化不一致（ODR）。不报：显式实例化声明、显式实例化定义、隐式实例化三者在所有翻译单元中完全一致

## 跨平台与二进制布局

- 结构体或容器的裸内存 `memcpy`/`reinterpret_cast` 读写：字节序、填充与对齐由实现决定，换平台或换编译器读出来的值不对。不报：已逐字段序列化，或数据只在本进程内使用
- 跨主机交换的整数未做字节序转换（C++23 的 `std::byteswap`、`std::endian`，或 `htons` 一族）：大端机上读成另一个数，而**测试通常只在小端机上跑**。不报：协议规定小端且实现已显式断言主机字节序
- `std::bit_cast` 或 `union` 做类型双关：前者要求两边同尺寸且可平凡复制，后者读非活跃成员在 C++ 里是未定义行为——本机看起来正常。不报：同一件事已用 `memcpy` 完成，或访问的正是活跃成员

## 并发

- 条件变量等待未包裹在 `while` 循环中，虚假唤醒后读到未就绪状态。不报：等待条件确实单调、不会回退
- `volatile` 当同步原语——它不提供原子性和内存序。不报：仅用于 MMIO 或 `sig_atomic_t` 信号处理
- 线程未 join 或 detach 后仍访问其栈上数据——UB，不是流程问题。不报：线程已证明在访问前终止
- `memory_order_consume` 的依赖关系被误用：编译器可将其提升为 `acquire` 或降级为 `relaxed`，语义不可靠。不报：已替换为 `acquire`
- 两个 `atomic` 之间用 `relaxed` 建立同步：只保证原子性，不保证可见性顺序。不报：已文档声明仅需原子性
