# 交付物

**一次评审的交付物只有一份：报告；不写报告时，就是对话里的结论或清单。** 分几段、立不立标题、摆不摆表、写多长——**由你按读者定**。

**但交付目录里不止一样东西。** 分过路或分过轮的评审，报告旁边必须有一本**合并后的账本**——它不是第二份报告，是每条结论的回源记录："查了哪些、哪些没查、哪条撤了、凭什么撤"，只有账本能逐行对上。账本缺席时报告就是孤证：读者没法核"没查出问题"是真的没有，还是没读。**报告里点到的条目要和账本对得上**：写"其余 N 条见账本"，账本里就得真有 N 条，且每条都能按位置找到。

**工作文件不是交付物。** 分路账本、分路记录、覆盖草稿、中间稿写在被审对象之外的临时目录。**进交付目录的只有两样：报告，和那一本合并后的账本**（分路账本与覆盖草表一律不进——留在那里，下一个人就得先判断"哪份是当前的"）。没分过路、也没分过轮的轻量评审只有报告。

## 报告要让人拿到什么

1. **发现**——位置（`文件:行号`）、它从哪来、问题与后果、最有力的反驳与什么会推翻它、刻意没查什么（见 `references/contract/report.md` 第 1 条）。
2. **同一处改动**——哪几条会被同一个改动一起消掉；指不出来就直说它们互相独立。**它问的是"这批问题共用几个根"，不是"我建议怎么做"**：不写取舍、不写选项、不写下一步动作——那些不在这份交付里。
3. **停止依据**——查了哪些、没查什么、为什么停，以及"它不证明什么"（见同一份第 3 条）。

**读者读完要能自己回答四件事**：这份东西在说什么（结论、范围、哪些没查）；每条结论有多硬——**是依据，不是形容词**；什么情况下它不成立；剩下什么没看。

## 写法

一句话能说清的不写第二句——说不清是还没想清。**每条自足**：离开这段对话也能读——要读者回头翻前文的指代（"上面""该条"）就是还没写清。写"可能有问题""建议关注"的，改成具体现象或删掉，前者读者没法核。**删的是修饰，反方与撤回条件一个字都不删。**

## 自查

想机械核一遍可以跑 `node scripts/check-claims.mjs <交付物>`；它只查能判真假的事：没填的槽位、替读者宣布"通过／能合"的词、写了"没有遗漏"这类完整性命题。**它不认形状，也不认你用什么词**——没有段名、没有表、顺序不同都不影响。`node scripts/review-check.mjs <目录> --root <对象根>` 再多管三件：目录里只有一份交付物、每条 `文件:行号` 能落到对象里、分路清单覆盖了对象根下该看的文件。它判的是"有没有对上"，判不了"判得对不对"，后者只能靠人读。

**跑没跑要说一句。** 跑了写结果（哪几条没过、你怎么处理的）；没跑写为什么——空着不算失败，但读者有权知道这份报告有没有被机械核过。
