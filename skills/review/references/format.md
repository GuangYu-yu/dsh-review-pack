# 交付物

**一次评审的交付物只有一份：报告；不写报告时，就是对话里的结论或清单。** 分几段、立不立标题、摆不摆表、写多长——**由你按读者定**。

**但交付目录里不止一样东西。** 分过路或分过轮的评审，报告旁边必须有一本**合并后的账本**——它不是第二份报告，是每条结论的回源记录："查了哪些、哪些没查、哪条撤了、凭什么撤"，只有账本能逐行对上。账本缺席时报告就是孤证：读者没法核"没查出问题"是真的没有，还是没读。**报告里点到的条目要和账本对得上**：写"其余 N 条见账本"，账本里就得真有 N 条，且每条都能按位置找到。**这个数是能核的**（`scripts/review-check.mjs`）：报告写了 N，账本里没在报告里出现的条数就得正好是 N。

**工作文件不是交付物。** 分路账本、分路记录、覆盖草稿、中间稿写在被审对象之外的临时目录。**进交付目录的只有这些：报告；分过路或分过轮时，一本合并后的账本；不走轻量路径时，一份执行档案**（分路账本与覆盖草表一律不进——留在那里，下一个人就得先判断"哪份是当前的"）。

## 报告要让人拿到什么

1. **发现**——每条分两行写。**事实**：位置（`文件:行号`）、引到的原文或命令输出、它从哪来（读源码／跑了命令／引了原文／推断）。**影响**：从这件事实到后果要走的每一步——会怎样、谁碰得到、什么条件下不成立——加上最有力的反驳与什么会推翻它、刻意没查什么。**事实成立不推出影响成立**；两样并进同一句，事实就在替影响背书（细则见 `references/contract/report.md` 第 1 条）。
2. **同一处改动**——哪几条会被同一个改动一起消掉；指不出来就直说它们互相独立。**它问的是"这批问题共用几个根"，不是"我建议怎么做"**：不写取舍、不写选项、不写下一步动作——那些不在这份交付里。
3. **停止依据**——查了哪些、没查什么、为什么停，以及"它不证明什么"（见同一份第 3 条）。

**读者读完要能自己回答四件事**：这份东西在说什么（结论、范围、哪些没查）；每条结论有多硬——**是依据，不是形容词**；什么情况下它不成立；剩下什么没看。

## 写法

同一个意思不说第二遍——重复会让读者以为第二处另有所指。**每条自足**：离开这段对话也能读——要读者回头翻前文的指代（"上面""该条"）就是还没写清。写"可能有问题""建议关注"的，改成具体现象或删掉，前者读者没法核。**删的是修饰，反方与撤回条件一个字都不删。**

## 执行档案

**轻量路径不另起一份档案**——把加载、仪器、缺口三样并进报告收尾那三行；省的是独立文件，不是这三样。其余情况报告旁边放一份 `run-record.md`，五节，写的时候你还在现场——**它之后不可重建**，事后补写的档案恰好证明不了它要证明的事（当时跑没跑）。

- **加载**：这一轮实际读了哪几册，一行一册，写成路径。**写完要能逐个对上**——列了却没用上，说明那册白读；用了却没列，说明报告的依据没有来源。**入口写的两份必读件必列**：`run-record-check.mjs` 核这一条，没列即失败；它核不了「列了是不是真读过」。
- **仪器**：跑了哪些脚本，一行一个，写成「命令行原文 → exit: 0 → 脚本自己打的那行汇总」（**`exit:` 这两个字母要写出来**，只写一个 `0` 分不清是退出码还是核出的条数）。**没跑的写「未跑：〈原因〉」**，原因不是「时间不够」这类，是缺了哪样东西才跑不了。**这一行点到的文件得在盘上**——被核的对象被删掉之后，这一行就没有证据了（`run-record-check.mjs` 核这一条）。
- **编制与证据档位**：谁写的正文、谁裁的、谁一手核了几处；另起一行写「证据档位：实测｜静态｜未证」，三选一，写成这三个词本身。**写了不等于真按这个编制做的**：先定与事后补写在产物上同形，档位写成「实测」也可能是编的——这两样核不了，只在正文里对上证据。
- **自评**：写成「自评：M / N」，M 是能被第二个人独立复核的条数（指得出位置与命令），N 是这一轮结论总数。**M 不能大于 N**；一条都举不出的写「自评：0 / N」。
- **缺口**：一行一条，写成「未取得：〈哪样材料〉 → 因此不能确认：〈哪一句结论／哪一个面〉」。缺口是从采集结果数出来的，不是自评一句「调查充分」——对象里有而你没取证的、取了证却没留命令的，都算。确实没有缺口就写「无」，并写一句凭什么（例如对象只有三个文件且逐个读过）。**跑得起来却写「未取得」不是缺口，是逃避**——能补的先补，补不了才写下来，并说明补它需要什么（见 `references/verification.md` 第五节）。

**报告与档案要对得上**：报告说跑了 `check-claims.mjs`，档案里没有那一行，二者必有一处是假的；报告里有一句「不能确认 X」，缺口节里就该有挡住它的那一条。**缺口不是免责声明**——它挡住的那句结论仍然要写，只是写成「未证」而不是「已查过」。

## 自查

想机械核一遍可以跑 `node scripts/check-claims.mjs <交付物>`；它只查能判真假的事：没填的槽位、替读者宣布"通过／能合"的词、写了"没有遗漏"这类完整性命题、以及不可见或双向控制字符（要引用就写成转义形式）。**它不认形状，也不认你用什么词**——没有段名、没有表、顺序不同都不影响。`node scripts/review-check.mjs <目录> --root <对象根>` 再多管几件：目录里只有一份报告、一本合并账本（分过路或分过轮时）与一份执行档案、每条 `文件:行号` 能落到对象里、分路清单覆盖了对象根下该看的文件。它判的是"有没有对上"，判不了"判得对不对"，后者只能靠人读。

**跑没跑，写进执行档案。** 跑了写结果（哪几条没过、你怎么处理的）；没跑写为什么——空着不算失败，但读者有权知道这份报告有没有被机械核过。`node scripts/run-record-check.mjs <交付目录>` 核这份档案的形状：四节在不在、仪器有没有命令行与退出码、未跑有没有原因、自评的 M 是否大于 N。**它核不了真假。****环境里没有 Node**（`node -v` 跑不起来）时，写「未跑：环境无 Node」，再把它核的那几条人工对着做一遍；整段跳过不算跑过。
