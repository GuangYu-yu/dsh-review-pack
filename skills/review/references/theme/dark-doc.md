**上游锚**：本册基于两份 HTML 快照——`原子.html`、`分子.html`（`sha256: <…>` / `<…>`；路径与哈希待填）。**锚没填或对不上时，不按本册判**，先跑下一节。

**权威值来源**：取值应在**第三处**——`dark.tokens.css` 或 `dark.json` 一类的单一来源。两份 HTML 各自复制了一份 `:root`，**它们本身已经是两个定义点，不是权威**。核验时以第三处为准；第三处不存在时，以两份 HTML 逐项比对代替——任何不一致先报「**双重权威**」。

## 零、先做的两件事

1. **锚对齐**：算两份快照的 sha256 与上游锚比对。不一致 → 报「**本册与上游漂移**」，**此后停止按本册判**，报告里写"以规格为准、本册待同步"。
2. **漂移自检**（锚没填时的替代）：本册引用的 token 名与类名，在上游里**应当整体成立或整体不成立**。**一片同时不存在 = 本册过期**（报漂移、停判）；**个别不存在 = 对象违规**（按对应条目报）。**两类不许报成同一句**：一个是尺子旧了，一个是被量的人错了。

## 一、来源与版本

- 本册引用的 token 名必须全部出现在权威来源中。本册有、权威来源没有的 token 名 → 报 [自动]（**成片不存在时改走第零节第 2 条**）
- 权威来源（`dark.tokens.css` / `dark.json`）是否存在。不存在 → 报「**缺单一来源**」，其后所有 token 一致性条目按"两份 HTML 互为副本、逐项比对"执行 [半可判定]
- 两份 HTML 的 `:root` token 集合逐项比对：出现任意一项不一致 → 报「**双重权威**」。不报：两份的 `:root` 逐项一致 [自动]
- 两份 HTML 的类名集合逐项比对：同一语义类在一份有、另一份无 → 报「**跨文件漂移**」 [自动]
- 两份 HTML 的语义映射逐项比对：同一标签或组件在一份用 `data-tone`、另一份写裸色 → 报「**跨文件漂移**」 [半可判定]

## 二、范围

**管**：**由这套模板派生的页面**（暗色技术文档 / 报告页）——容器、布局、标签、语义色、图标（`原子.html`），以及卡片、表格、流程图、徽章、提示条、代码块、指标卡、图表、时间线、键值清单、对比双列、任务清单、横向步骤、折叠块、标签组、引述、图片图注、树形结构、公式（`分子.html`）。

**不管**：营销页、通用 UI、移动端原生界面、表单控件与交互流程。

- 页面**不是**由这套模板派生的 → 本册不参与，在报告的**覆盖限制**里写明。不报：页面由这套模板派生
- 新增内容片段类型不在两份 HTML 中、但属于本范围 → 报，进报告的「**范围外新片段**」档，不按缺陷处理 [半可判定]

## 三、值层索引（token 名 + 语义，不写值）

取值见权威来源；本册只声明每个 token 的语义。

**颜色**
- `--line` / `--line-soft`：主分隔线 / 次分隔线
- `--fg` / `--fg-2`：主前景 / 正文前景
- `--muted`：次要文字、辅助说明
- `--arrow`：箭头、分隔带、序号、中性描边
- `--green` / `--orange` / `--red` / `--blue`：语义色基值（ok / warn / err / info）
- `--*-bg` / `--*-line`：对应语义色的浅底 / 描边
- `--code-bg`：行内代码与代码块底色
- `--card-line` / `--card-line-hi`：卡片默认边框 / 卡片 hover 边框

**字体**
- `--mono`：等宽字体栈（代码、版本号、数值、时间戳、序号）

**圆角**
- `--r-sm` / `--r-md` / `--r-lg` / `--r-pill`：小 / 中 / 大圆角 / 胶囊

**间距**
- `--p-sm` / `--p-md` / `--p-lg`：小 / 中 / 大内边距
- `--gap-sm` / `--gap-md` / `--gap-lg`：小 / 中 / 大间距

权威来源里有、本册未列的 token → 进「**规格缺口**」档的「值层索引漏项」，**不按缺陷报** [自动]

## 四、语义映射（场景 → token）

**文字**：正文段落 → `--fg-2`；标题（h2–h5）与加粗强调 → 权威来源里的最强前景 token；次要或未验证信息 → `--muted`；行内代码 → `--fg` + 底色 `--code-bg`；高亮底色文字 → 权威来源里的高亮 token。

**线条**：表格表头下边线 → `--line`；表格行下边线 → `--line-soft`；卡片内 `hr` → `--line-soft`；卡片边框 → `--card-line`、hover → `--card-line-hi`；箭头、流程连接、序号 → `--arrow`。

**语义色**：正常 / 通过 / 成功 → `data-tone="ok"`；警告 / 复查 → `warn`；错误 / 失败 → `err`；信息 / 引用 → `info`；中性 / 待定 → `neutral` 或不带 tone。

- 正文使用 `--fg` 而非 `--fg-2` → 报。不报：该处是 `分子.html` 中 `.card h2`–`.card h5`、`.card-head h2` 这四处，或确需主前景对比 [半可判定]
- 语义色直接写 `color: var(--green)` 而不走 `data-tone` → 报。不报：该处是 `原子.html` 的 `.demo` 演示区，或 `data-tone` 已在父级声明并向下继承 [半可判定]
- 表格线使用 `--line` 而非 `--line-soft` → 报。不报：该线是表头线（`th` 下边线）
- 卡片边框直接写 `--line` 而非 `--card-line` → 报

## 五、消费规则

**机制**：语义色通过 `data-tone` 消费，`--tone` / `--tone-bg` / `--tone-line` 沿 DOM 向下继承；组件自身只写 `var(--tone, 兜底值)`，不写具体色值；布局用 `.box` / `.grid` / `.row`，标签用 `.label`，图标用 `svg.i` + `<use>`。

**什么算绕开**

- 已有 token，消费处写裸值且该值多处复用（`--r-lg` 的值在 `.card` 里写成 `12px`、`#fff` 出现在多条标题规则）→ 报。不报：该值只出现一次、无复用 [自动]
- 组件内直接写 `color: var(--green)` 等语义色基值 → 报，应改走 `data-tone`。不报：该处是 `原子.html` 的 `.demo` 演示区
- 新写带 `border` 的 `<div>` 而不走 `.box` → 报。不报：该 `<div>` 是 `分子.html` 中 `.figure`、`.chart`、`.donut-wrap`、`.metric` 等组件内部的包裹层；但出现在卡片顶层（`.card` 的直接子级）→ 报 [半可判定]
- 新写 `display:grid` / `display:flex` 的行内样式而不走 `.grid` / `.row` → 报。不报：该行内样式出现在 `分子.html` 中 `.card-head`、`.flex-row`、`.bar-row`、`.donut-legend`、`.tl-item` 等已具名结构的组件内部 [半可判定]
- 出现 `.badge` / `.tag` / `.chip` 等新类名而不复用 `.label` → 报。不报：该部件是带专属结构的组件（见第六节判据）
- 内联 `<path>` 而不走 `<use href="#…">` → 报。不报：该 SVG 属于 `分子.html` 中的图表组件（`.spark`、`.line-chart`、`.donut`、`.tree` 的引导线）或任务清单的勾选图标
- 新写 `.title` / `.text` 覆盖原生标题与段落标签 → 报。不报：该处是组件内部结构（`.node .t`、`.tl-item .ttl`、`.step .ttl`、`.compare .col .h`、`.det summary`、`.chart-title`、`.callout .ttl`、`.metrics .k` / `.v`）

**tone 继承**：嵌套容器想保持中性 → 显式 `data-tone="neutral"`，或置于不带 tone 的容器内；`--tone:initial` 使自定义属性失效、`var()` 回落到消费端兜底值 → 报。不报：该处正是有意回落到兜底

## 六、分层规则（原子 / 分子 / 组件）

- **原子**：`.box`、`.grid`、`.row`、`.label`、`data-tone`、原生文本标签 + `code`/`strong`、`svg.i`。不可再分，只干一件事。
- **分子**：`badge` / `chip` / `ver` / `node` / `step`。用原子组合，自身不带专属 CSS。
- **组件**：`sparkline` / 折线图 / 环形进度 / 树形结构 / `timeline` / `det` / `codeblock` 等。带伪元素 / 动画 / SVG / 原生行为，各自带专属 CSS，不参与组合。

**新增部件的归属判据（三个问题）**：① 有伪元素 / 动画 / SVG 吗？② 有 JS 或原生行为吗？③ 有非盒属性的结构吗？任一 yes → 组件；三个全 no → 分子。

- 新增部件用原子组合实现，但满足三个问题中任一 → 报，应归组件层 [半可判定]
- 新增部件自带 CSS，但三个问题全 no → 报，应归分子层。不报：自带 CSS 是为了覆盖组件库默认样式，且已在该组件 CSS 中声明
- 分子中出现新类名而不复用既有分子 → 报，除非它是新分子并已更新本节清单 [半可判定]

## 七、正交层：与主轴正交的四类附加核验

本节核的不是"定义点唯一性"，是"**有没有提供**"。它们在别的册也有一份，本册只收与 dark 规格相关的部分。**本节命中与主轴命中在报告里分开列**：主轴进「已知风险点」，本节进「附加核验」档，不合并计数。

- **打印**：打印时卡片背景、边框、正文、代码块底色与暗色模式不同 → 报。不报：`分子.html` 中有 `@media print` 块且页面已引用它 [半可判定]
- **窄屏**：640px 以下 `.page` / `.compare` / `.toc ol` / `.kv` / 表格的适配是否与 `分子.html` 的 `@media (max-width:640px)` 块一致。不报：该块覆盖的类在页面中按该块适配
- **动效降级**：`prefers-reduced-motion:reduce` 下所有 animation / transition 时长降到最小。不报：`分子.html` 中有 `@media (prefers-reduced-motion:reduce)` 块且页面已引用它
- **无障碍**：`:focus-visible` 有可见轮廓、`::selection` 有明确底色；所有 `<img>` 有 `alt`；装饰性 SVG 有 `aria-hidden="true"`；可交互元素（`<button class="copy">`、`<summary>`、`<details>`）有可访问名称

## 八、规格缺口：规格本身未覆盖的维度

本节报的是**规格本身**的缺陷，不是代码绕开规格。命中进报告的「**规格缺陷**」档，不进「已知风险点」。

判据：同一值在多处复用，而权威来源中**无对应 token**。

- **动效参数**（时长、缓动）：两份 HTML 中 `transition` / `animation` 多处出现，`:root` 无对应 token → 报「规格未覆盖：动效参数」
- **字号 / 行高**：两份 HTML 中 `font-size` / `line-height` 多处出现，`:root` 无对应 token → 报「规格未覆盖：字号 / 行高」
- **高亮底色**（`.hl`）：取值只散落在类选择器里，`:root` 无对应 token → 报「规格未覆盖：高亮底色」
- **标题最强前景**（"标题白"）：多条标题规则共用同一值，`:root` 无对应 token → 报「规格未覆盖：最强前景」

不报：该值只出现一次、且无复用——那只是一次性取值，不构成规格缺口 [自动]
