**这里装的是"被指定的外观规格"的核验点**，一套规格一个文件，文件名＝规格名全小写（如 dark-doc.md、ios.md）。

**本件说的是"一份规格要能被核验，必须满足什么"**——写给自己用的规格，和别处交来的规格，量的是同一把尺子。所以它同时是**写作规范**和**验收标准**。

## 规格由两半组成

| 半 | 形态 | 谁产 |
|---|---|---|
| **可执行的那半**：颜色、字体、间距、阴影、动效的取值 | **DTCG JSON**（设计令牌社区组的标准），或由它生成的 CSS 变量 | 任何生产侧工具 |
| **不可执行的那半**：怎么用、什么算绕开、哪些不报 | **一册 md**，就是本目录里这一类 | 人，或那套工具顺带吐 |

**认标准，不认产品。** 别自造令牌格式（DTCG 已经存在、已经有人在用），也别为别人的产物格式（`design.md`、`DESIGN.md`、Storybook 提取物……）各写一册清单——**那本账追不完**，而且**读得懂一份说明，不等于能判代码有没有绕开它**。**格式转换是生产侧的事**：它吐一份 DTCG 加一册 md，核验就接得上。

## 没有声明，就不判

**这是本目录能不能成立的分水岭。** 「正文色不是 `#e6e6e6`」在两种情况下含义完全相反：

- 项目**声明**了它按这套规格做 → 那是**缺陷**；
- 项目没有声明 → 那只是**另一种风格**，一个缺陷都不是。

所以本目录的每一册**只在有声明时加载**；没有声明时一句话都不许报。**用对象自己的取值当规格不算声明**——把它的 `:root` 变量组当规格是循环论证，恒真，什么都核不了。那种情况下要审的是**内部一致性**，去 `references/lang/web.md`。

## 去哪里读声明

**按这个顺序探测，读到第一个就停：**

1. 项目根的 `theme.config.json` / `.yaml` / `.ts`——**首选**：机器可读、位置单点、可版本化；由它指向那一套的 DTCG 与那一册 md；
2. 一处被团队维护的文档声明（`docs/theme.md` 一类）；
3. 都没有 → **按"没有声明"处理**，本目录不参与。

**首选不是必须。** 这个包不能要求别人的项目改名——写死一种载体，等于对现存项目一律不工作。三种之外还有别的载体时，**以项目里实际存在的那份为准**，并在报告里写清你读的是哪一处。

## 参照物从哪来（样本这一侧的入口）

**声明**回答"规格是什么"，**样本**回答"像不像"。两种核验，缺一样就少一半。样本按这个顺序探测：

1. 项目里的**参照快照**（截图、录屏、真机导出，通常会有一个目录）；
2. `theme.config.*` 里指向的链接（设计稿、上游站点）；
3. 都没有 → 报「**缺参照物**」，**并把"该比却比不了"的那份交回去**（哪几屏、哪几个状态、哪几个尺寸）。**"缺参照物"是结论，不是免责。**

**有人替你看时，输入可以是"症状 + 截图"。** 对方说"这个按钮 hover 时没反应"就够了，**他不需要说出 `.btn:hover` 缺了 background**——指到位置是核验方的活（位置要自己定位过再写，见 `references/contract.md` 的来源与委派）。

## 核验动作：差分与穷举

**差分（对样本）**：同一个界面、同一个状态、同一个尺寸，两边并排看。**它把"我觉得不对"变成"这里和参照物不一样"**——后者指得到位置，前者只是感觉。**能跑浏览器时，差分就是实测**：截图脚本的命令、退出码、未经筛选的差异输出，就是三件套。

**穷举（对声明）**：漏了什么不会自己显形，**要主动触发**。维度固定四个，**取值从项目取**：

- **状态**：该元素交互模型下的可达状态集，逐一触发；
- **边界**：空 / 满 / 错 / 长 / 极短，逐一触发；
- **尺寸**：项目声明的断点，逐一拖；
- **偏好**：深浅、动效开关、对比度，逐一试。

**没触发过的，写进报告的覆盖限制**——**没触发就是没核过**。这与 `references/verification.md` 的"三份清单"是同一条纪律，只是用在观感上。

## 声明要能表达局部的覆盖

「整体用这套、代码块例外」是正常做法。声明里没有表达覆盖的地方，核验就会把**有意的偏离**报成缺陷——这跟清单里每条都要带「不报」是同一条纪律。**覆盖要署在声明里，署了就不报。**

## 一份规格要能被核验，得满足这几条

对内的写法、对外的验收，都是这几条。**过不了的规格不加载**——加载了也只能报出一堆不是缺陷的东西。

- **单一来源**：一套规格只有一处定义。两处都自称权威的，先当缺陷报，别替它挑一个。
- **每条都能回答"代码里哪一处违反了它"**：写成取值加上它的使用点（`正文前景 #e6e6e6`、`表格线只在下边 1px`）。**形容词指不到位置**（"克制的阴影""干脆的缓动"），一条都不收。
- **带「不报」**：没有例外清单的规格，会把有意的偏离报成缺陷。**例外与条目同等重要。**
- **半可判定的自报**：位置指得到、但"这两处是不是同一语义"要人判的，逐条写明，**不许和完全可判定的混排**——判据见 `references/lang/method.md` 的编辑规则。
- **标明来源与版本**（抄自哪份设计规范、哪一版），否则它会随时间无声地漂。

**推荐做法：把半可判定的条目在文末收成一张表。** 逐条自报是硬要求，汇总表是推荐做法——它让"不许混排"从**自觉**变成**可核对**：读者一眼看得出这份规格里有多少条要人判、有没有混进去的。表就两列：**出处（哪一节）** 与 **条目**。

**上游会变，所以还要一个锚。** 规格册是从某个上游（一份模板、一份规范、一份 token 文件）抄出来的，**上游一动它就会静默过期**。所以每一册要：

- **写明上游锚**（上游文件与它们的 sha256 或日期）。**它不是判死开关，是两级响应**：
  - **锚对不上**（上游动过）→ 报「**本册与上游漂移**」并写进覆盖限制，**继续判，但这一轮结论最高只到「待查」**——尺子旧了不等于不能说，是**不能当结论说**（与"复核不上的降到待查"同一条）。
  - **引用的名字成片失效** → **停判**：本册引用的 token 名与类名**整体**不存在时，那已经是另一套规格了，再判只会产出假缺陷。
  - **个别名字不存在** → 那是**对象违规**，按该条正常报。**"一片没了"和"一个没了"不许报成同一句**：一个是尺子旧了，一个是被量的人错了。
- **锚还是维护触发器**：上游一动，锚就把"该看一眼这册了"变成一个**可核的事实**。没有它，那件事是看不见的——**而看不见的过期，正是这份包最不愿留下的东西**。

## 一个项目可以有多套规格

同一份代码库里，"移动端用这套、桌面端用那套""品牌区用这套、内部工具区用那套""营销页用这套、产品页用那套"都是常态。**分区要署在声明里**（路径或目录 → 规格名），不要另立口头约定——**声明是唯一的接口，再开第二个家就一定会漂。**

- **有分区映射** → 各分区按**它归属的那套规格**核验。
- **多规格、却没有映射** → 等同于**没有可用的声明**：本册不参与，并在报告的**覆盖限制**里写明这件事。
- **映射漏掉了某些路径**（不归属任何分区）→ **报一条汇总**（漏了哪些），**不逐文件报**——条目数不是分量。

## "不好看"怎么报

**审美判断没有判据，所以它不能进发现。** 要提就在「发现的问题」末尾**单列一块**，开头写明"**以下不是缺陷，是审美意见**"：**不挂依据、不参与定级、不进条目计数**。

这不是客气：`references/contract.md` 要求每条结论挂依据，而"不好看"**挂不上任何一个依据**——判据不可指。把它混进缺陷，就是让口味借用结论的位置。

## 本件写什么、不写什么

**写的是三件事**：① **一份规格要能被核验，得满足什么**（上面那五条）；② **两份输入从哪来**——声明（规格是什么）与样本（像不像）；③ **核验时做什么动作**——差分、穷举，什么算"代码绕开了规格"。

**不写的是**："怎么从参照物提取出这套规格"（那是生产端的方法），以及**为别人的产物格式逐个写清单**（那本账追不完，而且它不产生判据）。
