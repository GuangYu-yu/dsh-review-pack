# 这里的自检脚本

都只判能机械判真假的事；都不判断一条发现对不对，也不读被审对象。**每一个都认一种固定的输入形状**——用之前先看下面这张表，别让它反过来规定你的交付物该怎么写。

| 脚本 | 要什么输入 | 查什么 |
|---|---|---|
| `verify-quotes.mjs` | 任何 markdown，里面有 `〈文件〉:〈行〉` 与反引号引文 | 锚点能不能落到源文件、行号越没越界、引文在附近是否逐字存在（`--root` 对象根，`--window` 附近行数） |
| `ledger.mjs check` | 一张表，表头自己定，但必须有一列叫「位置」（写 `文件:行号`）；其余列可有可无、顺序随意、编号可省 | 每行列数与表头对齐、位置带锚点、表头重名、同位置重复、正文里没转义的竖线 |
| `ledger.mjs merge` | 同上，多份 | 合成一份、重编号、去完全重复；源不合格时拒绝写盘 |
| `review-check.mjs` | 一个产出目录，可选 `--root`、`--lanes`（分路清单）、`--scope`（范围清单） | 见下面那张表：目录、账本、锚点、越界、派活范围、位置来源、分路覆盖、根挂载、欠报条数、没读的块 |
| `check-claims.mjs` | 任何 markdown，**不认形状** | 未填的槽位 `〈…〉`、替读者宣布"通过／能合"的词、"没有遗漏"这类完整性命题 |

退出码非 0 表示有失败项。**提示不是失败**：引文在锚点附近找不到、同一位置的不同问题这类只提示（`verify-quotes.mjs --strict` 才把引文算失败）；原样留着读一遍，不等于通过。

## 哪些规则有闸门，哪些只能靠读

把一条要求写成"必须"很容易，让它真被做是另一件事。这里的分工是：**能算出来的一律交给脚本，算不出来的才靠读**——写规则的人要知道自己写在哪一边。

| 要求 | 谁核 | 判法 |
|---|---|---|
| 交付目录只有一份交付物、一本合并后的账本，分路账本不在里面 | `review-check.mjs` | 数文件、认表头 |
| 账本每行列数对齐、位置带 `文件:行号`、编号连续、同位置不重复 | `ledger.mjs` | 逐行解析 |
| 每个锚点落得到源文件、行号不越界、引文在附近逐字存在 | `verify-quotes.mjs` | 读源文件比字符串 |
| 槽位填完、没有替读者宣布通过、没有完整性命题 | `check-claims.mjs` | 词形 |
| 报告与账本里的位置都在范围清单内 | `review-check.mjs --scope` | 路径比对 |
| 派活只派清单内的文件 | `review-check.mjs --lanes --scope` | 路径比对 |
| 报告里的位置在某一路的账本里，否则写出对得上的"回源 N 处" | `review-check.mjs --lanes` | 集合差 |
| 对象根下每个文件都有主责 | `review-check.mjs --lanes` | 集合差 |
| 条目够多时有「根」这一节，且每一行挂得上（编号或位置） | `review-check.mjs` | 存在性、引用 |
| 账本里有、报告里没出现的条数，写在报告里且数相等 | `review-check.mjs` | 数相等 |
| 范围清单里标了没读的块，报告点名或写出相等的数 | `review-check.mjs --scope` | 路径或数相等 |

**没有闸门、也不该有的**：后果推不推得出、根是不是真根（是不是同一个决定）、分组对不对、抽样够不够、该不该停、覆盖得够不够、反方是不是真反方、这条设计该不该留。这些只能读，判定要挂在具体位置上。

写一条要求之前先问：**它算得出来吗**。算得出来，就写进上面那半边，并给出仪器；算不出来，就别写成"每一个／一律／都"这种看起来会被执行的口气——写明靠读，并说清读到什么程度算判过。
