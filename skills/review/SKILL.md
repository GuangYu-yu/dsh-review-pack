# 评审入口

一次评审 = **1 个对象件 + 可选 1 个阶段件**。读完本节，只去读命中的那几个分册，**不要通读 `references/`**。

**分册在哪**：与本文件同目录的 `references/`，**确切路径以分发表那一行为准**（语言清单在 `references/lang/`）。宿主告知了技能基准目录就按它解析；没告知就用本文件所在目录。

## 一、先取输入

- **未提交的更改**：先 `git --no-pager diff --stat` 看规模，再决定整读还是 `git --no-pager diff -- <path>` 分片。只看 diff 会漏掉**未跟踪的新文件**——先 `git status --porcelain` 补齐，它们不在 `git diff` 里。
- **已提交的范围**：`git --no-pager diff <base>..<head>`，同样先 `--stat`。
- **拿不到 shell 时**：不要假装取过。直接向用户索取 diff（或让他把输出贴过来），并说明你只看到了这一部分（未跟踪文件、被跳过的路径都算没看到）。
- **先找项目既有的约定与已决事项**：约定文档、设计说明、决策记录、`AGENTS.md` 一类的项目记忆。**找到之后先确认它覆盖当前这个对象**——不同仓库、子树、目录各有自己的约定（行尾规则、禁改项、命名），拿邻居的规则当这里的规则，会把不适用的约束当成已满足。**已记录为"已评估并拒绝"的方案不得当作发现重提**——只能写成"确认它是否仍然成立"的问题。不知道这些就拿通用清单去套，会把项目已经否定过的设计当成修复建议交回去。
- **对象是一个目录、模块或整个项目时**：先声明**覆盖表**——哪些文件逐行读、哪些抽查、哪些不读及理由——再动手，并在报告里带上它。分给多路代理时，表里还要记**每一路是否收回**：没收回的范围按未审处理，不得出现在"已查未发现"里。小到一次上下文能读完的对象不必声明。
- **以 diff 为对象可以省下大量上下文，代价是看不到改动周围的全貌。** 任何结论依赖"这段代码之外还有别的东西"时，停下来去追那块上下文，再回来定性。

## 二、选件：按对象分发

| 被审的是什么 | 读哪个分册 |
| --- | --- |
| 补丁 / diff / PR / 变更集 | `references/diff.md` |
| 一份实现（文件、模块）的质量 | `references/code.md` |
| 结构与边界：模块划分、依赖方向 | `references/architecture.md` |
| 某语言的语义：所有权与借用、并发与异步、错误链、类型系统 | `references/lang/<语言小写>.md`（现成清单：Rust、Go） |
| 为一门没有现成清单的语言现场推导清单 | `references/lang/method.md` |
| 失败路径的设计：重试、超时、恢复、回滚 | `references/robustness.md` |
| 性能：代价随规模放大、往返、争用 | `references/performance.md` |
| 安全：判定权、越权、被信任的边界、秘密 | `references/security.md` |
| 正确性对抗推理：中断、中间态、外来输入 | `references/adversarial.md` |
| 验证本身与判定成败的脚本：三份清单、破坏性验证、降级标准、CI、门禁、发布检查 | `references/verification.md` |
| 运维面：可观测性、告警、回退、权限 | `references/operability.md` |
| 文档 / 配置 / 契约 / 数据 / 依赖的事实与一致性 | `references/docs-config.md` |
| 方案与意见的取舍裁决 | `references/style.md` |
| 已有结论的溯源与证伪 | `references/reasoning.md` |

阶段件（可选一个，不默认加载）：

| 阶段 | 读哪个分册 |
| --- | --- |
| 评审开场：先冻结问题边界，再推该审什么 | `references/derive.md` |
| 写代码 / 改代码 / 交付前 | `references/discipline.md` |

选件顺序：先按对象选一个。对象不明确时默认 `references/code.md`；只是准备宣称完成、没给出要审的改动时用 `references/discipline.md`。

**按后果升级（条件规则）。** 先问一句：这个对象会不会改动**不可逆状态**——磁盘 / 分区表 / 文件系统、数据库、资金、已发布的数据或接口？会，则 `references/adversarial.md` 与 `references/verification.md` 不是可选项：前者列出可能被搞坏的点，后者按三份清单与降级标准**实测**。报告里"失败路径不破坏"这一条必须带证据档位；只有静态推断时，就写"静态未发现破坏路径，动态未验"，不许写成结论。反过来，只读、可重跑、丢了也无所谓的对象（一次性脚本、报表、探针）不必升级——**升级要有理由，不是默认动作**。

升级是**叠加**：只多加对抗与验证两册，不替换对象件与阶段件；"准备宣称完成"仍走 `references/discipline.md`。

**拿不准选哪册**（只描述症状还是时序窗口、把关还是出验证方案、不知道从哪查起……共五组对照），以及**没有对应分册的对象**，见 `references/derive.md` 的「选件与覆盖边界」。

## 三、每条结论都要能核对

**1. 档位，只写这四个词之一。** **亲读**＝读了这段源码；**实测**＝跑了命令（附三件套）；**权威文档**＝附原文摘录＋版本＋日期；**推断**＝其余。**不许自造近义词**（"源码可证""确认过"都不算）；写"实测"就必须真跑过——**档位虚报比不写档位更坏**。

⤷ **会随版本、平台或时间变的事实**（API 签名、默认值、盘上布局、协议字段、某工具在某版本下的行为）：仪器是规范原文或上游源码，**代码注释与记忆都不算来源**；当场读代码或跑一次就能确认的不必补。**查不到就写"没查到"并交回**，不要用看起来合理的内容填；要标明它悬着。

**2. 最强反方。** 给结论找一个最有力的反驳，然后说它成不成立。找不出任何反驳，说明这个结论没被真正检验过，或者你挑的是软柿子。

**3. 什么会让我改变结论。** 具体到一个可观察的事实："如果 X 处确实有 Y，那我这条就不成立。"写不出这一句，说明结论不是从证据推出来的。

**4. 我刻意没查什么，以及原因。** 这一项最容易被省，也最能区分深入和敷衍。

边界：这四项不是让你把报告写长，每项一到三句。

**下结论之前的三条自检**：读，不要回想——判断来自当前读到的内容，不是对这类项目的一般印象，没把握就说不确定、说清还缺什么；区分"验证过"与"恰好没碰到"——跑过不等于验证了，测试全绿只说明它没碰到你改动的那条路径；证伪优先——对自产方案与外部方案用同等强度去证伪，别对自写的东西隐性宽容。

**提建议前问一句：它会不会反而让人以为已经处理过了？**

**定级不得高于档位。** 分轻重（严重/一般/待查）时，级别只反映"确认程度 × 后果"（后果含触发门槛），不反映语气：**没亲验过的不得定为最高级**；最高级要有一次独立复核垫底，**而且复核要换仪器**——换个人重读同一份材料只是同族的第二遍，只能证明自洽；复核不上的降到"待查"，并写清分歧在哪。分级口径要在报告里说清——但**级别不保证跨轮次可比**，要跨轮次比就比档位与仪器。

**否定与完整性命题的举证。**"没有别的调用点""无消费者""都已覆盖""没有遗漏"这类命题，**文本搜索证明不了**：命中只说明"存在"，空结果只说明"未发现"。给出这类结论时，必须同时写出**能证伪它的仪器**——编译器、测试、运行时、权威原文——以及具体命令或动作；**答不出仪器名，就不许据此删改，也不许写成结论**。要删要改先跑那次检查，别事后补。工具与脚本的绿灯同理：只证明"它覆盖到的那部分没报"——校验通过不等于没有问题。

**"我跑过了"同样要能重跑。** 实测这一档要给出**命令原文（含目标平台与全部参数）、退出码、未经筛选的输出**：用检索把输出筛过再看，等于蒙上仪器；增量缓存会跳过改过的文件、另一个 target 会给出另一份结果，"上次它是绿的"不算。三件套给不出就退回"推断"，但**必须交出交接实验**：命令、输入、期望（现在会看到什么、修好后应看到什么），别人能照跑——"本机跑不了"不是不交的理由，恰是交的理由；**本机跑得了的不许推给环境**。复核别人的"无 X"同理。**实测留下的临时文件、构建产物、临时调试代码，收尾前清掉**——留在对象里等于给下一个人换了一把看不见的尺子。

**"我推出来了"同样要留仪器。** 结论若关于**运行时行为**（崩溃后会怎样、某条路会不会被走到、几方并发时会不会交错），而对象又会动不可逆状态，就得交出交接实验；只有推理链、拿不出的，最高定到"待查"。**交接实验只在这两处要**（另加交不出实测三件套的，上一条）——亲读到的静态缺陷不在其列，套上只会稀释这个信号。

**来源与委派。** 把活分给子代理或并行多路时，明确要它回**发现清单**（不是导航摘要或文件概览）；代理给的结论是**二手事实，不是你的证据档位**——引用时必须标明"未亲验"，且只有你亲自复核过的条目才能进最高级。同时要行号与判据，便于抽查。

## 四、报告

**固定三段，缺一段算没做完**（发现为空时第一段写"无"，后两段照写）：

1. **发现的问题**——每条按第三节挂全四项；该交**交接实验**的另附（触发条件见第三节）。先合并重复——条目数不是分量；命中很多机械条目时，按第三节的口径挑出最强的几条，其余合并成简表。
2. **决策点**——有哪几条指向同一个决策点？两种形态**各写一条**：**同一判断被多路各写一遍**（收口后新增同类路径 N 处 → 1 处才值得）、**替沉默路径做决定的默认值**（沉默落在不安全侧就翻默认）。都不属于就写"零散问题，逐个修"——只有一条发现也要表态。
3. **停止审查的依据**——**读了哪几册，就照它自己的节表逐节表态**（有发现／无发现／不适用＋理由；目录类对象另附文件覆盖表）——**空格就是没查完**；再写停在哪里、已排除的可疑点（各带判据）。它**不是完整性命题**：不得写"没有遗漏""都查过了"，只能写"在覆盖表内未发现（仪器：…）"；"静态未验"每项挂**交接实验**。

- **用用户的语言写，段名就用这三个词**；不要另起小标题，也不要引入 `blocking`／`nit` 这类英文分级——本件按"确认程度 × 后果"定级（同时加载了别的评审件时，以本件为准）。
- **改动不要在报告里复述**（它已在 diff 里）：你另做的、diff 之外的编辑单独列出。这次任务同时包含评审与修复时，**两者分开报告**——静默地边审边改会让结论失去依据。
- 工具链会报的（编译器、linter）不写进发现——先让它喊。**它没跑过时，分册略去的那类不算查过。**

## 五、本件的范围与口径

- 讨论评审流程本身、给团队写规范，不在本件范围。被问**本件自身的口径**（定级标准、怎么写评审规范、评审流程）时，读完本件直接回答，**不要再读分册**——分册是拿来看对象的，不是本件的说明书。
