只列 Rust 的语言语义会直接产生的问题。每条都能指到具体代码位置，不需要判断口味。

## 先跑工具链，工具链报的不写进本件

`cargo clippy --all-targets -- -D warnings` 覆盖这些：`ptr_arg` / `let_and_return`（`&String` 参数、尾表达式返回 let 绑定）、`single_match` / `redundant_pattern_matching`、`derivable_impls`、`await_holding_lock`、`manual_filter_map`、`not_unsafe_ptr_arg_deref`（默认 deny）、`undocumented_unsafe_blocks`（需显式开启）。

rustc 自己就报的同样不列：未使用的生命周期参数（E0392）、迭代中修改集合（E0502）、非 `Send` 跨线程或跨 await、`unused_must_use`、公共 API 泄漏私有类型（`private_interfaces`）。

## 所有权与借用

- 函数的最后一条表达式是克隆，而克隆出来的值只用于返回：通常说明签名该收所有权，或者返回值该借用
- 签名接受所有权参数，函数体内却只做只读操作：调用方被迫放弃了它本来还能用的值
- 用 Box 做了堆分配，但值的生命周期完全可以确定在局部作用域内

## 错误处理（语言机制部分）

- 库代码里，把**调用方传入的参数**会触发的可恢复错误处理成 unwrap 或 expect——把调用方的问题变成了它自己的 panic
- 同上条件下使用 panic!。注意正当的例外：文档里已把 panic 写成契约、违反内部不变量、以及测试代码，这些都不报
- 公共 API 返回裸 Result，没有定义自己的错误类型，调用方无法稳定地区分失败原因
- 用 String 当错误类型，丢掉了分类和结构化上下文
- 错误转换时经过一次 to_string，原始错误类型在那一层就再也拿不回来了
- 同一错误类型的转换散落在多处手写，没有统一到 From 或 Display

## unsafe

- 存在安全替代方案时仍然用了 unsafe
- unsafe 块没有以 SAFETY 注释写明其成立前提
- unsafe 块覆盖了块内并不需要 unsafe 的行，把安全代码也划进了审计范围
- 手写 `unsafe impl Send` / `Sync` 而没有逐字段论证（字段含 `Rc`、`Cell`、`UnsafeCell`、裸指针时尤其）：`Send`/`Sync` 是编译器对并发唯一的静态证据，声明错了此后没有任何检查
- FFI 返回的原始指针直接交给调用方，没有封装成安全抽象

## 类型与模式匹配

- 同一业务语义在不同位置用了不同的基本类型
- 公共接口的 Option 参数，导致调用点到处传 None 而无法自明
- 同一个值在模式里被重复绑定，可以用 @ 合并
- From 或 Into 的实现丢掉了承载业务语义的字段——当两侧类型表达同一业务概念、而未使用的字段在下游无从取得时，这个转换要么不完整、要么本身就不该存在。仅取子集的视图类型转换是正当的，不报

## trait 与泛型

- 公共类型没有实现它本该实现的常用 trait，导致调用方到处写适配代码
- 用 Box<dyn Trait> 做参数或返回值，而所有可能的实现类型在编译期就已经确定
- 泛型参数约束了 'static，而实际传入的引用并不需要它，白限制了调用方

## 并发与异步

- 异步运行时是多线程调度时，在异步函数里调用会阻塞的标准库同步 IO（std::fs::File、std::net::TcpStream 等）。单线程本地执行器下没有这个问题，不报
- spawn 出来的任务，其 JoinHandle 被丢弃，于是任务的失败和 panic 无人处理
- 同一作用域内多次调用 borrow_mut 或 borrow，导致借用重叠——通常是把借用范围写得太长，而不是真的需要多次借用
- `async` 块或异步函数定义后从未被 `.await`、也从未被 spawn：它要么是死代码，要么是漏了执行——必须能说出是哪一个
- 用 `Rc<RefCell<T>>` 搭共享可变状态，而该值从未被多个所有者持有：那是把并发原语当成了绕开借用检查的工具
- **取消安全**：`select!`、`timeout`、竞速分支放弃一个 future 时，它可能停在任何 `.await` 点。判据是"这个 future 被丢弃时，**已经扣掉的进度、拿到的资源、写了一半的状态**由谁收拾"——`Drop` 覆盖了什么，并发原语（`Mutex`、信号量、许可）在取消路径上是否已释放。拿不出结论的，就把"哪些 future 是对取消安全的"写成必须公开的契约（逐条标注），而不是留给调用方猜

## 集合与迭代

- 对迭代器 collect 出临时集合并立刻再 iter() 转回去，这次往返没有必要
- 为了绕开借用检查而 clone，但克隆出来的值在后续作用域里从未被修改——顺序调一下就不需要克隆

## 宏

- 同一模式重复出现三处以上，而函数或泛型无法表达它（需要展开成不同语句、或需要生成标识符）时才考虑提取成宏。宏是比函数更重的抽象，够不上这个门槛就不要提
- 声明宏或过程宏生成的代码带上了调用方没有预期的 trait 约束或类型限定——这类约束应该由调用点决定
- 派生宏对类型名或字段名存在**隐式命名约定**（按名字推导行为），而约定只活在宏的实现里、没写进文档：改个名字就静默改了行为

## 可见性与接口

- 仅为了测试而放开的接口使用了 pub，而不是 pub(crate) 或 #[cfg(test)]
- pub use 重导出时把内部模块的路径结构一起暴露了出去

## 构建与依赖

- 依赖启用了默认特性集，而其中有一部分在项目里并未使用且可以关掉
- 同一个 crate 特性的条件编译判断在多个模块里各写了一遍，两份逻辑会漂移
- 公共 API 里用类型别名暴露了第三方 crate 的具体类型，等于把依赖固化进了接口
- 依赖声明了但代码里没有引用它的任何项（rustc 不报这个，得靠 `cargo-udeps` / `cargo machete`）：白白拖长构建，也扩大了供应链面
