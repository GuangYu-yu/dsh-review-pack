# 各语言审查清单

**一门语言一个文件，文件名就是语言名**（`rust.md`、`go.md`）。加一门语言＝放一个文件 + 在本件登记 + 在 `review` 的分发表里挂上名字。

| 语言 | 文件 | 覆盖 |
| --- | --- | --- |
| Rust | `rust.md` | 所有权与借用、错误处理、unsafe、类型与模式匹配、trait 与泛型、并发与异步、集合与迭代、宏、可见性与接口、构建与依赖 |
| Go | `go.md` | 错误链、资源与 defer、panic 与 recover、并发与 context、接口与类型断言、泛型、slice 与 map、unsafe 与 cgo、可见性与包、构建与依赖 |

## 怎么用

- **人看**：直接打开对应文件，或 `/lang-checklist` 进来按上表取用；也可以整份贴给别的工具。
- **评审时**：不用手动加载——`review` 的分发表会指向同一份文件。**物理上只有一份**：`dsh-review-pack/skills/` 下那份是 `npm pack` 必需的镜像，由 `check-pack` 逐文件核对，不是第二个可编辑的源。
- **不确定要不要固化**：先按 `review` 的 `lang.md` 现场推导，三次独立推导取交集才算收敛。没收敛先固化的，标成**候选池**并写明覆盖不保证，别当穷尽集用。

## 编辑规则

加语言、加条目时会反复重新争论的五件事，在这里定一次。

1. **按语言机制分轴。** 分类轴是这门语言的机制（所有权、错误处理、并发、类型系统），不是作者、来源、风格或"AI 标签"。
2. **不单列"AI 容易写出的坏味道"。** 高频问题只作为**挑条目时的优先级权重**，不成为分类轴——一旦成轴，主体会漂移、随模型过期、泛化性也没了。与 AI 相关的自检住在 `review` 的 `discipline.md`。
3. **工具链优先，且例外与条目同等重要。** 编译器、vet、linter、race detector 会报的不重复写；每条尽量写清**哪一类不报**——例外比清单本身更能防误报，这是清单可信度的来源。
4. **只给清单，不给报告契约。** 清单本体不标证据档位、不做简表；档位与四项收尾、条目多时合并简表，都以 `review` 技能为准。语言文件里不再各抄一份。
5. **语言无关的不进语言文件。** 失败路径、结构、垃圾与冗余各有自己的分册，由 `review` 的分发表负责分派。

## 加一门语言

1. 放 `./<语言小写>.md`。结构照 `rust.md`：首节只写**这门语言的工具链命令**并说清它报什么，其余按机制分小节，每条一句、能指到具体代码位置。**开头一行写「状态」**：`稳定核`（过了收敛检查）或 `候选池`（没过，明写覆盖不保证）。
2. 在本件顶部的 `description` 和上面的表里各加一行。
3. 把语言名加进 `review` 分发表那一行的"现成清单：…"。**那一行是入口件的预算，每门语言约 6 字符**；入口件每次评审全额加载，预算满时按"加一条就得让出一条"先腾地方。
4. 往 `pack-src/trigger-eval.json` 加一条该语言的分发正例。分发表一改，`tableSha256` 即失效，**分发回归必须重跑**——`score-trigger` 会拒绝给结论。

## 语言文件共用的口径

第 3、4、5 条不写进语言文件；约束由 `review` 的入口件承担：入口件第二节的分发表分派语言无关的对象，入口件第四节管"工具链会报的不写进发现"与报告形态。
