# dsh-review-pack

一个"审一切待交付的东西"的评审技能包：**一个入口技能 + 15 个分册 + 一个可扩展的语言清单技能**。

技能本体与宿主无关——`skills/` 下就是普通的 `SKILL.md` 技能集，正文只用 `git` 与通用命令，不调用任何宿主专有工具或服务。任何能读 `SKILL.md` 的宿主都能装；`cordis.patch.yml` 只是给 DSH 的可选装配层，别的宿主忽略它即可。

## 它解决什么

"帮我看看这段改动有没有问题"这句话，模型给不出稳定答案，通常是因为三件事没有约定：**该查哪些面**、**每条结论要交代到什么程度**、**什么时候算查完了**。本包把这三件事写成契约：

- **分发**：入口件按对象把活分派给对应分册，"对象是补丁 → 读 `references/diff.md`"是硬指令，不靠模型自己想起来。
- **证据档位**：每条结论必须交代它是**亲读**、**实测**、**权威文档**还是**推断**，并给出**最强反方**与"什么会让我改变结论"。
- **收口**：报告固定三段——**发现的问题 / 决策点 / 停止审查的依据**；多处症状同源时要求收成一个根因，而不是并列一堆。

## 装

**任何兼容 `SKILL.md` 的宿主**：把 `skills/` 下的 **`review/` 与 `lang-checklist/` 两个目录一起**复制到技能根，并**保持同级**。

```
<技能根>/
├── review/            入口件 + 15 个分册
│   ├── SKILL.md
│   └── references/*.md
└── lang-checklist/    各语言清单（一门语言一个文件）
    ├── SKILL.md
    └── rust.md
```

**为什么必须同级**：`review` 的分发表里，语言类条目指向"同级 `lang-checklist` 的 `rust.md`"，那个路径按 `<本件所在目录>/../lang-checklist/rust.md` 解析。只复制 `review/` 会让 Rust 那一条**静默**指向不存在的位置（其余 15 个分册都不受影响，所以这个坑不会自己暴露）。`lang-checklist` 标了 `disable-model-invocation`，不进模型目录、也不抢触发，复制它不增加常驻开销。

**DSH**：可以直接按 bundle 安装本仓库或 Release 里的 `.tgz`。

```bash
pnpm dsh plugin --profile <profile> add <本目录或 .tgz 路径>
```

## `skills/` 里有什么

`review/SKILL.md` 是入口件：取输入 → 按对象分发 → 交付契约 → 报告格式。它每次评审都会加载，所以刻意写得很短；细节按需读 `review/references/` 下的 15 个分册：

| 分册 | 对象 |
| --- | --- |
| `diff` / `code` / `architecture` | 补丁与变更集 / 一份实现 / 结构与边界 |
| `lang` / `robustness` / `performance` / `security` | 语言写法推导 / 失败路径 / 性能 / 安全 |
| `adversarial` / `verification` | 正确性对抗推理 / 验证本身 |
| `operability` / `docs-config` / `style` / `reasoning` | 运维面 / 文档与配置 / 方案取舍 / 已有结论 |
| `derive` / `discipline` | 阶段件：评审开场 / 写改代码与交付前 |

`lang-checklist/` 是各语言清单，一门语言一个文件（当前 Rust）。加一门语言＝**放一个文件，并在 `review` 的分发表里加一行**——只放文件而不加行，新清单不会被分发到。

## 已知边界

- **效果只验证到"报告纪律"**：一次 n=1 的对照显示，带本件与不带本件**发现能力没有差别**；差别在报告是否可审计（固定三段、逐条档位与最强反方、决策点收口、不可达结论标"待查"）。所以能声称的是"报告更规范"，**不能声称"评审结论更准"**。
- **不回答放行判断**：本包给的是审计材料，不给"能不能合"的 yes/no。
- **跨宿主未实测**；现有回归全部来自同一模型家族。
- **不要和其他评审技能包同时装**：定级轴不同（本件是"确认程度 × 后果"，PR 评论类技能通常是阻断优先级），混起来要人收口。
